# SPOTTER capability matrix

SPOTTER connects one fitness creator's own YouTube, Instagram (professional) and TikTok accounts over OAuth. It collects public trend candidates only where an official API allows it, scores trends deterministically, and uses AI only to classify and write. The three platforms do not expose the same data. This file records what each one gives SPOTTER, what it does not, and what is waiting on a platform approval. When a platform does not offer a capability, SPOTTER marks it unsupported instead of approximating it. When a platform does not return a value, the value stays `null`. The statuses below are the ones the app shows on its Connections page, generated by `src/core/connectors/{youtube,instagram,tiktok}/capabilities.ts`. The quotes and links that back them are here; `youtube/capabilities.ts` and `compliance/policy.ts` point to this file.

**Docs checked 2026-09-29** (`YOUTUBE_DOCS_CHECKED`, `INSTAGRAM_DOCS_CHECKED`, `TIKTOK_DOCS_CHECKED`). Quotes are verbatim from official pages fetched that day. Where the docs are silent, this file says "not confirmed".

## Verification state: nothing here has touched a live API

None of SPOTTER's live connectors has run against a real account. The tests in `test/connectors/{youtube,instagram,tiktok}.test.ts` run each connector against a fake `fetch`. That fake serves JSON from `test/fixtures/` and records every request the connector makes. The fixtures are **hand-written in the response shapes the docs show**, with synthetic IDs such as `vid-deep-squat` and `UC-small-coach`. They are not recordings of live responses. The one exception is the TikTok "error with HTTP 200" fixture, which copies the shape of a probe the research notes made against the real token endpoint with fake credentials. The tests therefore check that SPOTTER handles the *documented* behaviour. They do not show that the platforms behave as documented. Pipeline bookkeeping that involves no platform, such as the lost-access deletion clock, is tested against an in-memory database (`test/pipeline/accounts.test.ts`).

Labels used in the per-platform tables:

- **implemented, awaiting credentials**: the code and fixture tests exist. A real client ID/secret and a connected account are needed to exercise the feature.
- **implemented, awaiting credentials/approval**: the platform must also approve something first (YouTube III.L, Meta App Review, TikTok app review).
- **not implemented**: an official API exists, but SPOTTER does not call it.
- **not offered**: no official API serves SPOTTER's use case.

Demo mode runs these same connector classes with a simulated transport injected (`src/core/connectors/registry.ts`, `src/core/demo/transport/`). The demo therefore exercises the real OAuth handling, normalisers, pagination, quota accounting and error classification. It simulates the Instagram Facebook Login path and YouTube with the III.L flag on, which is the post-approval state. Demo rows carry `dataOrigin = 'demo'`, are shown as "simulated" and are never linked. The demo proves SPOTTER's plumbing, not the platforms.

Notes on the matrix:

1. **Configuration and scopes.** Without the platform's server credentials, the rows that need them read `not_configured`. YouTube's public rows (discovery, stats over time, audience size, comments) need only `YOUTUBE_API_KEY`. If the creator declines a scope, the rows gated on it read `needs_permission`:
   - YouTube: profile and content (`youtube.readonly`); analytics and shares & saves (`yt-analytics.readonly`).
   - Instagram: profile and content (the basic scope); analytics and shares & saves (the insights scope).
   - TikTok: profile (`user.info.basic`); content and shares (`video.list`).
2. **TikTok before a connection.** In live mode, TikTok's profile, content and shares rows read `needs_review` until an account is connected. TikTok gives no API access before app approval except to Sandbox target users (at most 10). SPOTTER cannot tell whether the app has been approved, so these rows read `needs_review` before the first connection even after approval. TikTok's other rows do not change.
3. **Instagram Hashtag Search refusals.** When Meta refuses Hashtag Search, discovery pauses it for 7 days and records the end date in the account's discovery cursor (`hashtagSearchBlockedUntil`). While that date is in the future, the Connections page replaces the Facebook Login discovery summary with *"Hashtag Search is not approved for this app yet (needs App Review for Instagram Public Content Access and Business Verification)"* (`src/server/queries/connections.ts`). The status stays `limited`.

## YouTube

APIs: YouTube Data API v3 and YouTube Analytics API v2, via the Google OAuth 2.0 web-server flow. An optional API key (`YOUTUBE_API_KEY`) lets public discovery run before a channel is connected.

### Auth and scopes

- **Endpoints.** Authorization is `https://accounts.google.com/o/oauth2/v2/auth` with `access_type=offline`, `prompt=consent`, `include_granted_scopes=true` and `state`. Code exchange and refresh go to `https://oauth2.googleapis.com/token`. Disconnecting calls `https://oauth2.googleapis.com/revoke` ([web-server guide](https://developers.google.com/identity/protocols/oauth2/web-server)).
- **Scopes.** SPOTTER requests `youtube.readonly` and `yt-analytics.readonly`, both read-only ([scopes](https://developers.google.com/identity/protocols/oauth2/scopes)). Analytics needs both: *"Important: API requests to this method now require access to the `https://www.googleapis.com/auth/youtube.readonly` scope."* ([reports.query](https://developers.google.com/youtube/analytics/reference/reports/query)).
- **Granted scopes.** SPOTTER stores the scopes listed in the token response's `scope` field, because *"When requesting multiple permissions (scopes), users may not grant your app access to all of them"* (web-server guide). If the Analytics scope was declined, `getCreatorAnalytics` returns `unsupported`, not an error.
- **PKCE.** SPOTTER sends PKCE (S256) by default (`GOOGLE_OAUTH_PKCE=true`). Google documents PKCE only for installed apps ([native-app guide](https://developers.google.com/identity/protocols/oauth2/native-app)), although its [discovery document](https://accounts.google.com/.well-known/openid-configuration) advertises `S256`. Not confirmed for web clients. Set `GOOGLE_OAUTH_PKCE=false` if Google rejects it.
- **"Testing" status.** While the OAuth app is in "Testing", it gets *"a refresh token expiring in 7 days"* ([OAuth overview](https://developers.google.com/identity/protocols/oauth2)) and is *"limited to up to 100 test users"* ([Manage App Audience](https://support.google.com/cloud/answer/15549945)).

### Quotas and rate limits

- **Defaults.** *"Projects that enable the YouTube Data API have a default quota allocation of 100 `search.list` calls, 100 `videos.insert` calls, and 10,000 units per day combined for all other endpoints."* *"Daily quotas reset at midnight Pacific Time (PT)."* Every extra results page is charged ([quota calculator](https://developers.google.com/youtube/v3/determine_quota_cost)).
- **batchGetStats.** `videos.batchGetStats` (added 2026-06-03) sits *"in its own granular quota bucket. The method's default quota is 10,000 units per day"* ([revision history](https://developers.google.com/youtube/v3/revision_history)). It is missing from the quota calculator table.
- **SPOTTER's accounting.** SPOTTER reserves every metered call before sending it (`src/core/connectors/quota.ts`). It tracks the three buckets per Pacific day and keeps 10% back for manual refreshes (`YOUTUBE_QUOTA_RESERVE_FRACTION`). With the defaults, 3 scheduled runs × 16 queries use 48 of the 100 search calls. The budgets are set by `YOUTUBE_DAILY_QUOTA`, `YOUTUBE_SEARCH_DAILY_LIMIT` and `YOUTUBE_BATCH_STATS_DAILY_LIMIT`. The 100 searches a day, not the 10,000 units, is what limits discovery.
- **Errors.** `quotaExceeded` (403) is never retried. `rateLimitExceeded` and `userRateLimitExceeded` are retried with backoff ([errors](https://developers.google.com/youtube/v3/docs/errors), [core errors](https://developers.google.com/youtube/v3/docs/core_errors)).
- **More quota** requires a compliance audit ([Quota and Compliance Audits](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits)).

### Available, unavailable, approval-gated

- **Available.** The own channel, its uploads, the public counts of any public video, and the channel's own Analytics. For Analytics, *"The user authorizing the request must be the owner of the channel"* ([channel reports](https://developers.google.com/youtube/analytics/channel_reports)).
- **Gated by III.L.** Developer Policies III.E.4.h: API clients must not *"(ii) access or use API Data to create new or derived data or metrics"* ([policies](https://developers.google.com/youtube/terms/developer-policies)). Custom scores, content categorisation and storing statistics beyond 30 days need the III.L opt-in. That opt-in is *"only applicable to audited developers with analytics use cases"* and is requested through the quota-extension form ([derived-metrics policy](https://developers.google.com/youtube/terms/derived-metrics-policy)). Until `YOUTUBE_DERIVED_METRICS_APPROVED=true`, SPOTTER shows YouTube data exactly as reported. It keeps both own and other creators' YouTube data out of trend scoring, AI categorisation and personalisation, and it does not fetch comments (`src/core/compliance/policy.ts`). Whether simple ratios such as views/hour would be allowed without approval is a judgement call the notes could not settle. SPOTTER assumes they are not.
- **Storage.** *"an API Client must not store statistics retrieved as Non-Authorized Data for more than 30 days"* (III.E.4.b). SPOTTER's daily retention job:
  - deletes other channels' YouTube snapshots after 30 days, or after 1,080 days (36 × 30, just under 36 calendar months) with the flag;
  - deletes other channels' videos not re-read within 30 days (III.E.4.d).

  Disconnecting in SPOTTER revokes the token (best effort) and deletes the account's data immediately. III.D.2.c.i allows up to 7 days.

  If the creator revokes access in Google's settings instead, deletion must happen *"within 30 calendar days of that revocation"* (III.D.2.c.ii). SPOTTER handles it like this:
  - The first refused token refresh marks the account as needing reconnection and records the time once, in `platform_accounts.access_lost_at`. Retries do not reset it; a successful refresh or a reconnect clears it.
  - The retention job deletes the channel's collected data once `access_lost_at` is 28 days old, two days inside the 30-day limit (`LOST_ACCESS_MARGIN_DAYS` in `src/core/pipeline/retention.ts`). The margin absorbs the delay before SPOTTER notices the loss at its next run, plus the once-a-day timing of the retention job. That holds as long as collection runs at least once a day; the default schedule runs three times.
  - `test/pipeline/accounts.test.ts` checks that retries do not restart the clock and that the data is still there at day 25 and gone by day 31.
- **Unavailable.** A Shorts flag, sounds or music, transcripts of other creators' videos, public share/save/dislike counts, watch time, retention or traffic sources of third-party videos, exact subscriber counts, and trending by topic ([videos resource](https://developers.google.com/youtube/v3/docs/videos), [channels resource](https://developers.google.com/youtube/v3/docs/channels)).

### Freshness

- **Data API vs Analytics.** Google says: *"If your application requires real-time statistics for individual videos, such as current view, like, or comment counts, use the YouTube Data API's `videos.list` method instead of the YouTube Analytics API."* Analytics data *"typically introduces a latency of 48 to 72 hours"* ([data model](https://developers.google.com/youtube/analytics/data_model)). SPOTTER therefore keeps the Data API view count and stores Analytics views separately as `extraMetrics.analyticsViews`.
- **View counting changed twice.** From 2025-03-31, Shorts count each start or replay. For all formats, `viewCount` counts *"the moment a video begins to play"*. The field docs date that change 2026-08-24; the revision-history entry is dated 2026-08-27. The app's note says "late August 2026" ([videos resource](https://developers.google.com/youtube/v3/docs/videos), [Analytics revision history](https://developers.google.com/youtube/analytics/revision_history)). Views/hour series can jump at these dates.

### Gotchas

- Search results carry no statistics. Every results page needs a follow-up `videos.list` call ([search resource](https://developers.google.com/youtube/v3/docs/search)).
- *"Specifying a sort order other than `relevance` might result in a smaller or incomplete result set, particularly when combined with date filters"*, so SPOTTER uses `relevance`. `regionCode` returns videos *"that can be viewed in the specified country"*, which is not regional trending. With `relevanceLanguage`, *"results in other languages will still be returned if they are highly relevant"* ([search.list](https://developers.google.com/youtube/v3/docs/search/list)).
- The uploads playlist's order is not documented. SPOTTER stops paging only when an entire page is older than its time window.
- There is no Shorts flag, and the policy guide forbids to *"Infer or estimate the content category/type of a video or channel"* ([guide](https://developers.google.com/youtube/terms/developer-policies-guide)). Every YouTube item is stored as `mediaType = 'video'` with its duration as reported.
- `subscriberCount` *"is rounded down to three significant figures"*. The field definition gives no exception for the owner, so the creator's own count is rounded too. Hidden counts become `null` ([channels resource](https://developers.google.com/youtube/v3/docs/channels)).
- `captions.download` *"requires the user to have permission to edit the video"* and the `youtube.force-ssl` scope ([captions.download](https://developers.google.com/youtube/v3/docs/captions/download)).
- Public videos have no sound or music field. Analytics' `SOUND_PAGE` traffic source is limited to the creator's own videos and does not identify the sound ([dimensions](https://developers.google.com/youtube/analytics/dimensions)).
- The maximum number of IDs per `videos.list`, `channels.list` or `batchGetStats` call is not documented. SPOTTER assumes 50, and the code marks this as an assumption on `BATCH` in `youtube/connector.ts`. It is untested against the live API. SPOTTER does not send `maxResults` with `id`, which the `videos.list` page says *"is not supported for use in conjunction with the `id` parameter"* ([videos.list](https://developers.google.com/youtube/v3/docs/videos/list)).
- `batchGetStats` lists `failedVideoIds`. Tracked videos missing from a refresh are marked `unavailable` ([batchGetStats](https://developers.google.com/youtube/v3/docs/videos/batchGetStats)).

## Instagram

Instagram Platform, Graph API `v26.0` (set by `META_GRAPH_API_VERSION`; *"v26.0 | July 29, 2026 | TBD"* in the [versions table](https://developers.facebook.com/docs/graph-api/changelog/versions)). Only professional (Business or Creator) accounts are supported. *"There are two Instagram API configurations: Instagram API with Instagram Login serves Instagram professional accounts without requiring a linked Facebook Page. Instagram API with Facebook Login serves Instagram professional accounts linked to a Facebook Page."* ([overview](https://developers.facebook.com/documentation/instagram-platform/overview)). *"Your app can either use Facebook Login or Instagram Login but not both"* ([App Review](https://developers.facebook.com/documentation/instagram-platform/app-review)). The path is therefore a server setting, `INSTAGRAM_AUTH_MODE` (default `instagram_login`).

### Quotas and rate limits

- **Business Use Case (BUC) limit.** Owned-data endpoints on both paths share one Business Use Case limit per app-and-user pair: *"Calls within 24 hours = 4800 * Number of Impressions"*.
- **Platform limit.** *"All endpoints are subject to Instagram Business Use Case rate limiting except for Business Discovery and Hashtag Search endpoints, which are subject to Platform Rate limiting."* The Platform limit is *"Calls within one hour = 200 * Number of Users"* for app tokens. For user tokens, *"we do not reveal actual call count values"* ([rate limiting](https://developers.facebook.com/docs/graph-api/overview/rate-limiting)).
- **SPOTTER's handling.** SPOTTER parses `X-App-Usage` and `X-Business-Use-Case-Usage` and reports the highest percentage used. It treats error codes 4, 17, 32, 341, 613 and 80002 as rate limiting ([error handling](https://developers.facebook.com/docs/graph-api/guides/error-handling)). When one arrives, the Business Discovery or hashtag loop stops and keeps what it has already collected. A rate limit that escapes a step stops Instagram for the rest of the run, and the scheduler backs off.
- **Hashtag budget.** *"You can query a maximum of 30 unique hashtags on behalf of an Instagram Business or Creator Account within a rolling, 7 day period."* Requests to `recent_media` and `top_media` *"count against the 30 hashtag limit, even when you already have the hashtag's ID"* ([Hashtag Search](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search)). SPOTTER:
  - records when each tag was first queried;
  - caches hashtag IDs, which the docs describe as *"both static and global"*;
  - stops adding new tags at 25 per 7 days;
  - pauses Hashtag Search for 7 days when Meta refuses the permission.

### Available, unavailable, review-gated

- **Own account, both paths.** No App Review needed: *"If your app only serves your Instagram professional account or an account you manage, Standard Access is all your app needs."* Also: *"Because of the limited scope of Standard Access, some features might not work properly until your app has been granted Advanced Access."* ([overview](https://developers.facebook.com/documentation/instagram-platform/overview)).
- **Business Discovery, Facebook Login only.**
  - The docs say to *"identify the targeted business with the `username` parameter"*. There is no search, so SPOTTER needs exact usernames.
  - It works on Business and Creator accounts only, and *"Data about age-gated Instagram Business IG Users will not be returned"*.
  - Returned media carry no insights, `saved_count` or `shares_count` ([guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/business-discovery), [reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery)).
- **Hashtag Search, Facebook Login only.** *"In order to use this API, you must undergo App Review and request approval for: the `Instagram Public Content Access` feature; the `instagram_basic` permission"*. IPCA *"is only available with business verification"* ([IPCA](https://developers.facebook.com/docs/features-reference/instagram-public-content-access)).
- **Never available.**
  - Personal accounts: the API *"can not be used to get data for media owned by personal Instagram accounts"* ([IG Media](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media)).
  - Account search by keyword.
  - The author of hashtag media, and views on hashtag media.
  - Insights, saves or shares on other accounts' media.
  - The track an existing Reel uses.

### Freshness

- **Insights.** *"Data used to calculate metrics can be delayed up to 48 hours."* The media-insights period *"is automatically set to `lifetime`"*, so SPOTTER builds its own time series by polling on every run. When data is missing, *"the API returns an empty data set instead of `0`"*, and SPOTTER keeps it as `null` ([media insights](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media/insights), [account insights](https://developers.facebook.com/documentation/instagram-platform/api-reference/instagram-user/insights)).
- **Fields.** How fresh the `like_count`, `comments_count` and `view_count` fields are is not documented.
- **Facebook Login data access.** *"The expiration period for data access is 90 days, based on when the user was last active."* No `instagram_*` permission is on the list of permissions that do not expire ([auth vs data](https://developers.facebook.com/documentation/facebook-login/auth-vs-data)).

### Gotchas

- **Hashtag results.** *"You cannot request the `username` field on returned media objects"*, and there are no views. `recent_media` *"Only returns media objects published within 24 hours of query execution"* and is not chronological. Creator fields stay `null`, and the UI says "Author not shared by platform".
- **`view_count`.** It is available through Business Discovery only and *"includes both paid and organic metrics"*. Since 2026-04-22 it combines Instagram and Facebook views for crossposted video. SPOTTER stores it with `extraMetrics.viewCountIncludesPaid = 1`. The creator's own media have no view field; their views come only from insights.
- **`media_url`.** It *"is omitted for video media that contains copyrighted or licensed audio … This applies to all video media, including media the app user owns"*. It is also omitted for other accounts' Reels with downloads turned off ([IG Media](https://developers.facebook.com/documentation/instagram-platform/reference/instagram-media)). SPOTTER uses `thumbnail_url` (or `media_url` for images) and links to the permalink.
- **`media_audio_type`.** It is `MUSIC` or `ORIGINAL_SOUND`, for video only. No documented field returns the track or `audio_id` of an existing Reel. The Audio API lists authorised tracks for publishing, on Facebook Login only.
- **`media_product_type`.** REELS vs FEED is documented as Facebook-Login-only, so on Instagram Login, Reels are stored as `video`.
- **`like_count`.** It is omitted when the owner hides likes on media read through another endpoint, and SPOTTER keeps it as `null`.
- **`caption`.** The IG Media reference labels it *"Available for Instagram API with Facebook Login only"*. The notes read that as probably referring to the `@` clause, but this is unverified. SPOTTER requests `caption` on both paths.
- **Public fields only in Business Discovery.** Field expansion on another account returns only fields the IG User reference marks Public: `biography`, `followers_count`, `id`, `media_count`, `username`, `website`, `alt_text` ([IG User](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user)). Display names are not among them, so watchlist creators are shown by username.
- **Deleted media.** Error 100 with subcode 33 is treated as "not found". That code comes from community threads; the official error page does not list it.

## TikTok

TikTok Login Kit for Web plus Display API v2 (`https://open.tiktokapis.com/v2`) are the only TikTok APIs SPOTTER calls.

### Auth and scopes

- **Authorization.** `https://www.tiktok.com/v2/auth/authorize/` with `client_key`, `response_type=code`, a comma-separated `scope`, `redirect_uri` and `state` ([Login Kit for Web](https://developers.tiktok.com/docs/en/login-kit-web)). There is no PKCE: *"PKCE applies to desktop, iOS, and Android but not web."* ([Login Kit overview](https://developers.tiktok.com/docs/en/login-kit-overview)).
- **Tokens.** Code exchange and refresh go to `POST https://open.tiktokapis.com/v2/oauth/token/`; disconnecting calls `POST /v2/oauth/revoke/` ([token management](https://developers.tiktok.com/docs/en/oauth-user-access-token-management)).
  - The access token *"is valid for 24 hours after initial issuance"*.
  - The refresh token *"is valid for 365 days after the initial issuance"*.
  - *"The returned `refresh_token` may be different than the one passed in the payload. You must use the newly-returned token"*. SPOTTER stores the rotated token and the `refresh_expires_in` from every response.
  - Whether refreshing extends the 365-day window is not documented. The app tells the creator to expect to reconnect yearly.
- **Scopes.** SPOTTER requests `user.info.basic`, `user.info.profile`, `user.info.stats` and `video.list`.
  - *"The scope `user.info.basic` will be added by default for all apps with Login Kit"* ([scopes overview](https://developers.tiktok.com/docs/en/scopes-overview)). For the rest: *"Anything beyond that requires pre-approval in your app configuration. Users can grant a subset of what you request."* ([Login Kit overview](https://developers.tiktok.com/docs/en/login-kit-overview)).
  - SPOTTER asks `/v2/user/info/` only for fields the granted scopes allow. `user.info.basic` alone now returns only open ID, union ID, avatars and display name ([migration bulletin](https://developers.tiktok.com/bulletin/user-info-scope-migration)).
- **Deauthorization.** The signed `authorization.removed` webhook deletes the account's tokens and data immediately ([webhook events](https://developers.tiktok.com/docs/en/webhooks-events)).

### What SPOTTER calls

| Call | What SPOTTER sends | Scope | State |

| `POST /v2/video/list/` | `max_count=20`, cursor, ≤25 pages, stopping at the lookback window. Fields: `id, create_time, cover_image_url, share_url, video_description, duration, title, like_count, comment_count, share_count, view_count` | `video.list` | implemented, awaiting credentials/approval |

### Quotas and rate limits

- **Display API limit.** Each of `/v2/user/info/`, `/v2/video/list/` and `/v2/video/query/` allows 600 requests: *"Request rate calculation is based on a one minute sliding window."* Going over returns HTTP 429 with `rate_limit_exceeded` ([rate limits](https://developers.tiktok.com/docs/en/tiktok-api-v2-rate-limit)). The docs do not say whether the limit applies per app, per user or per token. SPOTTER makes one `user.info` call and at most 25 `video.list` calls per run.
- **Active user cap.** An "active user cap" exists, but its value is not published ([FAQ](https://developers.tiktok.com/docs/en/getting-started-faq)).

### Review and approval

- **No access before approval.** *"Please note that you will not have access to the APIs until your application has been approved."* ([FAQ](https://developers.tiktok.com/docs/en/getting-started-faq)). Until then there is Sandbox: *"You can create up to 5 sandboxes"* and *"You can add up to 10 accounts"* as target users, each added with its login credentials ([Sandbox](https://developers.tiktok.com/docs/en/add-a-sandbox)). SPOTTER follows this: in live mode its TikTok profile, content and shares rows read `needs_review` until an account is connected. The connector notes say only Sandbox target users can connect before approval.
- **Eligibility.** *"Apps must not be for private or personal use."* and *"Apps that are still in development or testing will not be approved."* ([App Review Guidelines](https://developers.tiktok.com/docs/en/app-review-guidelines)). A self-hosted tool for one creator may fail review. The docs do not address this case.
- **Website.** The guidelines also say *"Your Privacy Policy and Terms of Service links must be visible on the website URL without having to open a menu to view them"*. SPOTTER's sign-in page shows its `/privacy` and `/terms` links directly. However, *"Your website URL cannot be a landing page or login page. You must have an externally facing fully developed website."* A SPOTTER installation publicly offers only its sign-in page and the two policy pages, which may not meet that bar. Apps created after September 9, 2024 must also verify the Terms of Service, Privacy Policy and web URLs ([Register your app](https://developers.tiktok.com/docs/en/getting-started-create-an-app)).
- **Developer Terms.** §III.3(c) forbids use *"without TikTok's express written consent, for any commercial or unauthorized purpose"*. §III.3(h) forbids building *"any profiles, databases, or similar records on any individual, device, content, or browser"* ([Developer Terms](https://www.tiktok.com/legal/page/global/tik-tok-developer-terms-of-service/en)). SPOTTER stores only the creator's own video metrics, deletes them on disconnect, and never uses TikTok data as third-party trend evidence (`policy.ts`). Legal review is still advised before commercial use.

### Freshness

- **Counts.** How fresh Display API counts are is not documented. TikTok's own guide fetches *"the user's recent TikTok videos every 12 hours"* ([Display API get started](https://developers.tiktok.com/docs/en/display-api-get-started)). SPOTTER re-lists them on every run (3 a day by default).
- **Cover images.** `cover_image_url` *"has a TTL of 6 hours"* ([video object](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-object)). SPOTTER stores it for immediate display only, so older thumbnails break.

### Gotchas

- The token endpoint can return an error body with HTTP 200 (seen in the research notes' live probe). SPOTTER checks the body's `error` field, not only the status.
- `/v2/video/list/` returns *"the given user's public TikTok video posts"* ([video list](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list)). The docs do not say how photo posts or friends-only posts are handled.
- `title` and `video_description` are capped at 150 characters. Hashtags exist only inside that text, and SPOTTER parses them out of it.
- There is no field for sound or music, saves or favorites, structured hashtags, transcripts, watch time, reach or demographics. `is_aigc` exists, but SPOTTER does not request it.
- Redirect URIs must be absolute `https` URLs, static (*"Parameters will be denied"*) and without a fragment ([Login Kit for Web](https://developers.tiktok.com/docs/en/login-kit-web)). SPOTTER's default `APP_URL` is `http://localhost:3000`, which does not meet that rule. Whether `https://localhost` is accepted for Web apps is not documented.

Connectors must never substitute a guessed value for a missing one."* Items start from `emptyContentItem()`, where every optional field is `null`. The parsers in `src/core/connectors/normalize-utils.ts` return `null` for missing, negative or malformed values; they never return 0.

| `creatorFollowerCount` | `subscriberCount` (3 s.f.; `null` if hidden) | own `followers_count` | `followers_count` | `null` | own `follower_count` (needs `user.info.stats`) | as typed |

**Provenance.** Every item and every metric snapshot (`content_metric_snapshots.source`) carries a `MetricSource`:

- `public_api`: counts from a platform endpoint, including the public counters on the creator's own posts.
- `owner_insights`: a snapshot of one of the creator's own posts that combines the run's public counters with the private analytics read at the same moment (YouTube Analytics, Instagram insights). `mergeOwnerInsights` (`src/core/pipeline/store/content.ts`) writes one snapshot per run. Views, likes and comments keep the public counter when both sources report them. Shares, saves and reach come from insights, which is the only source that reports them for these platforms. Read `owner_insights` as "contains owner-only values", not "every value came from insights".
- `manual`: entered by the creator through assisted capture.

There is no "simulated" source. Demo rows are identified by `dataOrigin = 'demo'`.

`dataOrigin` separates `live`, `demo` and `manual` rows. A live workspace reads `live` and `manual` rows.

## Isolation of unsupported features

Unsupported capabilities are kept separate at four layers.

1. **Capability report.** Each connector's `capabilities(ctx)` returns one `CapabilityItem` per `CAPABILITY_KEYS` entry, with its status, summary, scopes and doc links. Anything the official API does not offer for SPOTTER's use is `unavailable`. Something the API offers but SPOTTER V1 does not use is `not_implemented`; today that is only Instagram comments. The Connections page renders every item with:
   - its badge ("Not offered by the API" for `unavailable`, "Not used by SPOTTER" for `not_implemented`);
   - the summary and "docs" links;
   - the connector's notes;
   - the line "Checked against official documentation on 2026-09-29."
2. **Call results.** For an unsupported capability, a connector method neither throws nor fakes data. It returns `{ status: 'unsupported', capability, reason }` (`unsupported()` in `types.ts`). The current cases:
   - **YouTube:** `getCreatorAnalytics` when `yt-analytics.readonly` was not granted.
   - **Instagram:** `getCreatorAnalytics` without the insights scope. `getPublicDiscoveryCandidates` on Instagram Login. `refreshPublicMetrics` always, because other accounts' media cannot be read by ID; the watchlist is re-read through Business Discovery instead.
   - **TikTok:** `getCreatorContent` without `video.list`. `getCreatorAnalytics`, `getPublicDiscoveryCandidates` and `refreshPublicMetrics` always.
   - **Comments:** `getTopComments` is optional and exists only on the YouTube connector.
3. **Pipeline.** `collect.ts` records such a step as `unsupported`, with the reason. That is not a failure: it does not make the run partial, trigger backoff or change the connector's health. The Collection page shows an amber "‹step› · unsupported" badge with the reason on hover. Each platform runs in isolation, so one failing never stops another.
4. **Data and UI.** Missing values stay `null`. The UI renders them as "n/a" (with the tooltip "This platform does not expose view counts here"), "—", "no baseline" or "Author not shared by platform", never as 0. A score component whose inputs are missing gets `score: null`, and its weight is redistributed (`ScoreComponent`). A trend pattern's `audio` is `null` when no connector exposes audio.

   Every post row names its platform in text, next to the coloured dot: evidence lists, the trend detail table, the Performance post table and the Captured list. Captured posts are marked "captured by you" and demo posts "simulated".

On top of this, `src/core/compliance/policy.ts` decides per platform whether derived analytics may use the data:

- **YouTube:** no, for own or other creators' data, until `YOUTUBE_DERIVED_METRICS_APPROVED=true`.
- **Instagram:** yes, for both.
- **TikTok:** yes for the creator's own videos; never for other creators' content.
- **Assisted captures (decided outside `policy.ts`):** analysed on every platform, because `analyze.ts` and `trends.ts` treat them as the creator's own observations rather than API data (see below).

The platform policies are also shown to the user:

- **App footer (live workspaces).** For each platform whose data can appear (connected platforms, plus YouTube when an API key is set), the footer shows its attribution ("Data from YouTube", "Data from Instagram", "Data from TikTok"), its terms links and its `restrictionNote` (`src/app/(app)/layout.tsx`). YouTube's note stays until the III.L flag is set; TikTok's note concerns its Developer Terms.
- **Connections page.** The YouTube card says *"By connecting YouTube you agree to be bound by the YouTube Terms of Service · Google Privacy Policy."* The other cards show their attribution and terms link.
- **Demo workspaces.** The footer reads *"Demo data: the creators, posts and numbers are simulated. Nothing here comes from a platform."*
- **Privacy policy and terms of use.** SPOTTER serves public `/privacy` and `/terms` pages (`src/app/privacy/page.tsx`, `src/app/terms/page.tsx`). No sign-in is needed. The privacy policy is generated from the code and the server configuration, so it reflects which AI providers are configured and the retention periods in `policy.ts`. Both pages are linked from the sign-in page, from setup (whose sign-up form says creating an account means agreeing to them, *"including the YouTube Terms of Service"*) and from every app page's footer. They were written against these requirements:
  - **YouTube III.A.1:** API clients *"must also state in their own terms of use that, by using those API Clients, users are agreeing to be bound by the YouTube Terms of Service"*. The terms page says so and links to the YouTube Terms of Service.
  - **YouTube III.A.2:** the privacy policy must be *"prominently displayed and easily accessible to users at all times"*, *"notify users that the API Client uses YouTube API Services"*, *"reference and link to the Google Privacy Policy"*, explain revocation through the Google security settings page, and give contact details ([policies](https://developers.google.com/youtube/terms/developer-policies)). The privacy page covers each point, but the contact line is a real address only when `PRIVACY_CONTACT` is set; otherwise it just says to ask the operator (`OPERATOR_NAME` names the operator).
  - **Meta Platform Terms §4:** the privacy policy must explain *"how Users may request deletion of that data"* ([Platform Terms](https://developers.facebook.com/terms)). The privacy page has a deletion section that links to the data-deletion status page. The operator still has to enter the policy URL in the App Dashboard.
  - **TikTok:** see the review notes in the TikTok section.

  The pages follow the published requirements. Whether Google, Meta or TikTok reviewers accept them is not known.

## Optional assisted capture

**What it is.** The creator pastes the link to a post they saw while browsing. They can also add the text and the numbers the app showed them: handle, followers, views, likes, comments and posting date (`src/core/assisted/capture.ts`, `/capture`).

**What it is not.** SPOTTER does not fetch the link or call any API about it. It does not automate a browser, log in anywhere, solve or bypass CAPTCHAs, rotate IPs or use any anti-detection technique. The module contains no network code; it only parses the URL string.

- **Off by default.** It stays off unless `ASSISTED_DISCOVERY_ENABLED=true`. When it is off, the page explains how to enable it and the server actions refuse. Captures belong to live workspaces only.
- **Accepted links.** YouTube `watch?v=`, `/shorts/` and `youtu.be`; Instagram `/p/`, `/reel/` and `/reels/`; TikTok `/@handle/video/<id>`. Anything else is rejected.
- **Stored as manual data.** Captures carry `dataOrigin = 'manual'`, `metricSource = 'manual'` and `discoveredVia = 'manual_capture'`. Numbers are stored as typed; forms like "12k" and "1.2m" are accepted. Negative numbers and future dates are dropped. Shares, saves, reach, duration, audio and media type stay `null`. SPOTTER never refreshes a capture, and the creator can delete one.
- **Analysed on any platform.** Captures are analysed and clustered with the next collection run on YouTube, Instagram and TikTok alike (`src/core/pipeline/analyze.ts`, `trends.ts`). SPOTTER treats them as the creator's own observations, not platform API data, so it does not apply the per-platform API data policies to them. That is SPOTTER's position; no platform document addresses notes a user types in. A capture becomes a trend candidate only if its posting date falls inside the trend look-back window (14 days by default). Without a posting date, the capture date is used.
- **Labelled.** Evidence lists and the trend detail table mark captures "captured by you", with the tooltip "Captured by you; numbers are what you saw at the time".
